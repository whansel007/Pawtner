## Data flow on the phone (today)

1. On launch, `App.tsx` requests `/api/today`; the server assembles scheduled occurrences and ledger events into `DerivedDose[]`.
2. Heart, streak and the lifetime hearts total (`dog.heartsTotal`, sum of every day's hearts since the first scheduled dose) come from shared selectors/rules, derived on read from the full dose history; only heart, streak and mood are cached in `dogs`. Persisted decisions update the cached dog mood. The phone does not show `heartsTotal` yet.
3. Dose confirmation, BP entry, and walk completion write events through the API. Weekly Summary uses `/api/caretaker/summary` (also read for the caretaker's name); caretaker consent and threshold save through `/api/escalation-settings`.
4. Settings has a demo clock. It calls `/api/agent/decide` at the selected local time. Where the latest decision shows (branch `claude/tricks-decisions`): urgent / safety decisions (`URGENT_DECISIONS` in `config/decisions.ts`: `emergency_995`, `see_gp_soon`) stay on Home under the next-dose card; every other decision shows at the top of Milestones (`homeDecision` / `routineDecision`, `lib/decisions.ts`). Health still shows the latest decision (and the 995 / see-GP card) as before. "Why?" (`DecisionLogCard`) shows a plain en.json reason per rule (`decisionLog.why.<ruleId>`, generic line for unknown rules) and only the observations listed in `WHY_OBSERVATIONS`, with labels; no rule ids, field names or ids. Opening it scrolls it into view inside its scroll area, clear of the bottom nav (`lib/useRevealWhenOpen.ts`).
5. `SceneBackdrop` draws the garden; `lib/useSceneGround.ts` measures where the dog stands (portrait Home: top of the chips; other portrait screens: top of the content card; landscape: on the lawn in the left column, see `DOG_PLACEMENTS` and `LANDSCAPE_MEDIA_QUERY` in `config/scene.ts`) and publishes CSS variables so the art's lawn line and the dog's feet meet. It also publishes the dog's box (`--dog-top`, `--dog-height`) so the tap bubble (`PetBubble`, in the toast slot under the hearts) never covers the head.
6. Home shows `NextDoseCard` (next due/missed dose, then upcoming). "Taken" → prototype proof screen → API event; status is re-derived from the ledger. If the API call fails, `handleDoseVerified` marks the dose taken locally (not saved; the next successful `/api/today` replaces it) and gets a `celebrate` decision from local `decide()` via `lib/agent.ts`. The proof screen's "Compare with my pill" sends the photo to `POST /api/pill-verify`, which compares it with the medicine's original pill photo (T2-08); 422 = no original set yet (`proof.check.noReference`).
7. Intro: cover → dedication (auto-advances after `DEDICATION_HOLD_MS`, `config/intro.ts`) → Home.
8. Navigation: `lib/useNavigation.ts` keeps the screen and a short history (`lib/navigation.ts`). Top-level screens (home, health, milestones, walk, settings) show "Home"; drilled-down screens show "Back" and return to where they were opened from. Every non-Home screen uses `components/FullCard.tsx` (fixed frame, back button, inner scroll).
9. Day/night (T2-10): `lib/useDayPhase.ts` picks the garden from the real clock in `SENIOR_TIMEZONE` (`config/scene.ts`, "Asia/Singapore" until the API exposes `users.timezone`), re-checked every minute and on returning to the app; the Settings demo clock overrides it. Day is 07:00–18:59 (`shared/day-phase.ts`). At night `components/NightStars.tsx` adds six twinkling knitted stars over the garden (config in `config/stars.ts`, in % of the art box inside `SceneBackdrop`, so they crop with the art; reduced motion = still). `/care` doesn't use the phase (it has its own garden image). When the phase changes, the night garden (with its stars) cross-fades over the day garden in `PHASE_FADE_MS` (2 s, `config/scene.ts`; opacity only, instant under reduced motion, no fade on first load). Each garden has its own art box, aspect and ground line, so both stay on the dog's feet. The inactive garden is mounted only after the active one has loaded (both images, day 110 KB and night 205 KB, end up loaded).
10. **Filming a time of day (no DB writes).** Open `/?time=21:00` (any 24-hour `HH:MM`, or `?time=morning` = 09:00, `?time=evening` = 21:00; presets in `config/demo.ts`): the app opens with the **scene time** at today's date at that time in `SENIOR_TIMEZONE`, already in the right garden (no flash). Scene time is look only (`sceneTime` in `App.tsx`): it never re-reads `/api/today` at another time, so hearts, mood and doses stay on the one real state (before 15 Oct night, morning vs evening showed different hearts: hosted data gave 2 hearts/content at 09:00 and 0/sleepy at 21:00 for the same day). Invalid values are ignored with one console warning. The parameter stays in the URL, so a reload re-applies it; `/care` ignores it (it never mounts the phone `App`). In the app: Settings > Demo > "Morning (9:00)", "Evening (21:00)" set the scene time and go Home with the 2 s fade; "Real time" clears it. None of these call the API. Only the agent demo clock ("Run agent at this time", `demoNow`) reads and writes at another instant and calls `POST /api/agent/decide` (writes a decision); it clears the scene time. "Reset demo" (Settings > Demo, `lib/demoReset.ts`) clears the phone's demo keys (`DEMO_STORAGE_KEYS`: restock request and choice, clinic memo, visit notes) and reloads without `?time=`; API data (doses, readings, walks, treats) is not touched: re-run P1's seed for that. Conversion helper: `lib/demoTime.ts` (`tests/unit/demoTime.test.ts`).
11. **Buddy clips and bark** (branch `claude/buddy-clips`). `DogLayer` runs `lib/useBuddyClip.ts`; `DogStage` draws the clip as a `<video muted playsInline>` inside the dog's body, in a box with the art canvas's shape, offset by `CLIP_CANVAS` (`config/clips.ts`) so the clip's first frame lies on the still. Format: `pickClipSource` (`lib/buddyClips.ts`) gives Safari/WebKit the HEVC-alpha `.mov` and other browsers the VP9-alpha `.webm` (or nothing). Triggers: the Wave trick (see 12) plays `buddy-wave` when content and `buddy-joyful` when joyful; `handleDoseVerified` (online and offline paths) bumps `celebrateRequest`, and Home plays `buddy-joyful` once if Buddy is joyful there. No clip when sleepy, attentive, dizzy, with reduced motion, or on load. The still stays until the video fires `playing`, then hides; breathe/hop pause while a clip is mounted; `ended`/error/`play()` rejection/7 s timeout bring the still back. The accessory sits in `.dog-stage__accessory` and fades out with the still (150 ms) because it can't follow the clip's moving head. Both clips preload when Home is idle. Bark: `lib/useBark.ts` (one shared Audio element, `PET_REACTIONS.soundOn`, `/assets/bark.mp3` user-supplied) for the tap rotation and the round paw button (`.companion-button`, toast kept). `/care` has no clips.
12. **Tricks** (branch `claude/tricks-decisions`). Tricks come from `/api/milestones` (offline: `mock/milestones.ts`) through one shared hook, `lib/useMilestones.ts` (DogLayer loads it once; Milestones refreshes it on each visit; while loading no tricks count). `config/tricks.ts` maps trick names to performances: Sit → basic reactions, Wave (7-day streak, was "High five") → the wave clip; Roll over and New trick have none yet. Tapping Buddy (`usePetReaction`) cycles hop → hearts → bubble → bark → wave; the wave is in the cycle only once Wave is earned and the clip can play (not sleepy, attentive, dizzy, reduced motion, or an unsupported browser). On Milestones, earned trick cards are buttons: Sit → the next basic reaction, Wave → the clip (or a basic reaction if the clip can't play); a sleepy Buddy's Wave card shows `milestones.waveSleepy` instead. The card asks App (`trickRequest`), which hands it to DogLayer. Rules: `lib/tricks.ts`, tested in `tests/unit/tricks.test.ts`. Milestones order: routine decision, progress, World & wardrobe, Souvenirs, Tricks.
13. **Health, restock, treats** (branch `claude/health-care`, tentative). Health rows (week summary, From the Doctor, Screen for Life, Link to Healthy 365) use one primitive, `components/ActionRow.tsx` (48 px icon box, same text edge and chevron). Links and the Healthy 365 logo (`public/assets/healthy365-logo.webp`, user-supplied) live in `mock/home.ts`. No upload, no OCR, no interpretation. Settings > "Jamie, caretaker" is information only. Restock: `useRestockHelp` (App) shows `RestockCard` on **Reminders** while the medicine picked from `GET /api/medications` (`pickRestockAlert`; mock `restockAlert` offline) has ≤ `RESTOCK_SOON_DAYS` (= `DEMO_RULES.restockDaysOfSupply`) days left; Home's "See all" gets a dot while it waits. "Ask Jamie to help" → `requestRestockHelp()` in `lib/restockHelp.ts` (localStorage `pawtner.restockHelp`, demo only); "I'll get it myself" → the card stays with "You'll get this one yourself." (`pawtner.restockSelf`, per medicine; the card always stays while the supply is low, only the status line changes). The gift chip calls `api.latestTreat()` and shows its message (marks it seen); no treat or no API → "A treat from Jamie is waiting for Buddy!".

## Caretaker web (`/care`)

- **Routing.** `mobile/src/main.tsx` switches on the path: `/` renders the phone `App` (unchanged), `/care` and `/care/*` render `care/CareApp.tsx`, lazy-loaded so the phone bundle and CSS stay as they were (phone CSS build output verified byte-identical to `main`). `lib/pathname.ts` (`usePathname`, `navigateTo` = `history.pushState`, `replacePath`) keeps browser back/forward working; no router dependency. Routes and the redirect rule live in `care/routing.ts`: `/care` landing, `/care/sign-in`, `/care/week`, `/care/alerts`, `/care/settings`; signed-in pages without a persona `replaceState` to the picker; unknown `/care/*` paths show the landing.
- **Deep links on Vercel.** `mobile/vercel.json` rewrites `/care` and `/care/:path*` to `/index.html` (Root Directory is `mobile`). P1's EdgeOne copy needs the same SPA rewrite for `/care/*`.
- **Demo sign-in (front end only).** `/care/sign-in` lists three personas from `care/data/personas.ts`: the senior (name from `summary.senior.name`; choosing her opens `/`), the caretaker who **gets check-ins** (`summary.caregiver.name`, mock "Jamie" if the API has none) and the caretaker with **updates only** (mock slot `MOCK_UPDATES_ONLY_CARETAKER`, "Alex", in `care/data/mock.ts`). The chosen caretaker slot (`checkIns` / `updatesOnly`, not a name) is kept in `sessionStorage` key `pawtner.care.persona` (wrapped in try/catch); Log out clears it and returns to `/care`. No passwords, accounts or database changes.
- **Visibility.** Rules in `care/lib/rules.ts`: updates-only caretakers don't see caring moments of kind `check_in` (`visibleMoments`), and see Alerts read-only with a calm note; `checkInLock()` allows editing the threshold only for the check-ins caretaker, with consent on (`escalation.optedIn`) and the API reachable.
- **Data mapping.** Today ring = `today.doses` taken / total (counts only, never medicine names). Streak = `dog.streak`; seven weekday hearts, the last `min(streak, 7)` filled (`streakHearts`, `recentDays`). Caring moments = `summary.caringMoments` (time via `Intl` in the viewer's local zone; the API has no senior time zone yet). Questions for the doctor = `summary.doctorQuestions`. Consent = `escalation.optedIn`; one shared threshold stepper, minimum `DEMO_RULES.caretakerMinimumThreshold`, saved with the existing `api.updateEscalationSettings({ optedIn, threshold })`. Message preview = `care.web.alerts.preview` in `en.json` with the senior's name and the threshold, no medicine name. Settings shows dog and senior names from data, a weekly-summary preview (visible moments, streak, walks, doctor-question count) and "Medication editing: coming soon".
- **Treat and restock (This week, tentative).** "Send Buddy a treat" (`care/hooks/useCareTreat.ts`) calls the same `api.sendTreat(message)` (POST `/api/treats`) the phone used, with the message "{{caretaker}} sent {{dog}} a treat!" so Rose's gift chip says who sent it; offline the button is disabled with a calm notice. - **Look.** `care/care.css` holds one token block scoped to `.care-root` (cream/forest palette, Inter, radii, spacing); every class starts with `care-`. The dog is ours (`DOG_IMAGE_BY_MOOD` from `config/scene.ts`, by `dog.mood`); the design's cartoon dog is not used. Garden art: `public/assets/care-garden.webp` (1920×800, 121 KB, from the design's 2.8 MB PNG), path in `care/config.ts`.
