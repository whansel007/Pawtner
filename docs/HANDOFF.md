## Data flow on the phone (today)

1. On launch, `App.tsx` requests `/api/today`; the server assembles scheduled occurrences and ledger events into `DerivedDose[]`.
2. Heart, streak and the lifetime hearts total (`dog.heartsTotal`, sum of every day's hearts since the first scheduled dose) come from shared selectors/rules, derived on read from the full dose history; only heart, streak and mood are cached in `dogs`. Persisted decisions update the cached dog mood. The phone does not show `heartsTotal` yet.
3. Dose confirmation, BP entry, and walk completion write events through the API. Weekly Summary uses `/api/caretaker/summary` (also read for the caretaker's name); caretaker consent and threshold save through `/api/escalation-settings`.
4. Settings has a demo clock. It calls `/api/agent/decide` at the selected local time; Home shows the saved decision with its rule, observations, reasoning, and wording source.
5. `SceneBackdrop` draws the garden; `lib/useSceneGround.ts` measures where the dog stands (portrait Home: top of the chips; other portrait screens: top of the content card; landscape: on the lawn in the left column, see `DOG_PLACEMENTS` and `LANDSCAPE_MEDIA_QUERY` in `config/scene.ts`) and publishes CSS variables so the art's lawn line and the dog's feet meet. It also publishes the dog's box (`--dog-top`, `--dog-height`) so the tap bubble (`PetBubble`, in the toast slot under the hearts) never covers the head.
6. Home shows `NextDoseCard` (next due/missed dose, then upcoming). "Taken" → prototype proof screen → API event; status is re-derived from the ledger. If the API call fails, `handleDoseVerified` marks the dose taken locally (not saved; the next successful `/api/today` replaces it) and gets a `celebrate` decision from local `decide()` via `lib/agent.ts`. The proof screen does not upload an image.
7. Intro: cover → dedication (auto-advances after `DEDICATION_HOLD_MS`, `config/intro.ts`) → Home.
8. Navigation: `lib/useNavigation.ts` keeps the screen and a short history (`lib/navigation.ts`). Top-level screens (home, health, milestones, walk, settings) show "Home"; drilled-down screens show "Back" and return to where they were opened from. Every non-Home screen uses `components/FullCard.tsx` (fixed frame, back button, inner scroll).
9. Day/night (T2-10): `lib/useDayPhase.ts` picks the garden from the real clock in `SENIOR_TIMEZONE` (`config/scene.ts`, "Asia/Singapore" until the API exposes `users.timezone`), re-checked every minute and on returning to the app; the Settings demo clock overrides it. Day is 07:00–18:59 (`shared/day-phase.ts`). At night `components/NightStars.tsx` adds six twinkling knitted stars over the garden (config in `config/stars.ts`, in % of the art box inside `SceneBackdrop`, so they crop with the art; reduced motion = still). `/care` doesn't use the phase (it has its own garden image). When the phase changes, the night garden (with its stars) cross-fades over the day garden in `PHASE_FADE_MS` (2 s, `config/scene.ts`; opacity only, instant under reduced motion, no fade on first load). Each garden has its own art box, aspect and ground line, so both stay on the dog's feet. The inactive garden is mounted only after the active one has loaded (both images, day 110 KB and night 205 KB, end up loaded).
10. **Filming a time of day (no DB writes).** Open `/?time=21:00` (any 24-hour `HH:MM`, or `?time=morning` = 09:00, `?time=evening` = 21:00; presets in `config/demo.ts`): the app opens with the demo clock at today's date at that time in `SENIOR_TIMEZONE`, already in the right garden (no flash), and refreshes `/api/today?now=…` (GET only). Invalid values are ignored with one console warning. The parameter stays in the URL, so a reload re-applies it; `/care` ignores it (it never mounts the phone `App`). In the app: Settings > Demo > "Morning (9:00)", "Evening (21:00)" set the demo clock (and the datetime input), refresh today, and go Home with the 2 s fade; "Real time" clears the demo clock. None of these run the agent; only "Run agent at this time" calls `POST /api/agent/decide` (writes a decision). Conversion helper: `lib/demoTime.ts` (`tests/unit/demoTime.test.ts`).
11. **Buddy clips and bark** (branch `claude/buddy-clips`). `DogLayer` runs `lib/useBuddyClip.ts`; `DogStage` draws the clip as a `<video muted playsInline>` inside the dog's body, in a box with the art canvas's shape, offset by `CLIP_CANVAS` (`config/clips.ts`) so the clip's first frame lies on the still. Format: `pickClipSource` (`lib/buddyClips.ts`) gives Safari/WebKit the HEVC-alpha `.mov` and other browsers the VP9-alpha `.webm` (or nothing). Triggers: tap while content → `buddy-wave`; tap while joyful → `buddy-joyful`; `handleDoseVerified` (online and offline paths) bumps `celebrateRequest`, and Home plays `buddy-joyful` once if Buddy is joyful there. No clip when sleepy, attentive, dizzy, with reduced motion, or on load. The tap rotation (`usePetReaction`) still advances: hop/hearts are replaced by the clip, bubble and bark still happen. The still stays until the video fires `playing`, then hides; breathe/hop pause while a clip is mounted; `ended`/error/`play()` rejection/7 s timeout bring the still back. The accessory sits in `.dog-stage__accessory` and fades out with the still (150 ms) because it can't follow the clip's moving head. Both clips preload when Home is idle. Bark: `lib/useBark.ts` (one shared Audio element, `PET_REACTIONS.soundOn`, `/assets/bark.mp3` user-supplied) for the tap rotation and the round paw button (`.companion-button`, toast kept). `/care` has no clips.

12. **Health, restock, treats** (branch `claude/health-care`, tentative). Health rows (week summary, Doctor's tiny tasks, Screen for Life, Link to Healthy 365) use one primitive, `components/ActionRow.tsx` (48 px icon box, same text edge and chevron). Links and the Healthy 365 logo (`public/assets/healthy365-logo.webp`, user-supplied) live in `mock/home.ts`. Doctor's tiny tasks = a photo of the clinic memo (`components/ClinicMemoRow.tsx`, `lib/useClinicMemo.ts`, `config/health.ts`): file input `accept="image/*" capture="environment"`, downscaled to a ≤1000 px JPEG data URL in localStorage `pawtner.clinicMemo` (in memory if storage fails), thumbnail in the row, tap → `PhotoViewer` with "Replace photo". No upload, no OCR, no interpretation. Settings > "Jamie, caretaker" is information only. Restock: `useRestockHelp` (App) shows `RestockCard` on **Reminders** when `restockAlert` (mock) has ≤ `RESTOCK_SOON_DAYS` days left and wasn't dismissed today; Home's "See all" gets a dot while it waits. "Ask Jamie to help" → `requestRestockHelp()` in `lib/restockHelp.ts` (localStorage `pawtner.restockHelp`, demo only); "I'll get it myself" → hidden until the next local day (`pawtner.restockDismissedOn`). The gift chip calls `api.latestTreat()` and shows its message (marks it seen); no treat or no API → "A treat from Jamie is waiting for Buddy!".

## Caretaker web (`/care`)

- **Routing.** `mobile/src/main.tsx` switches on the path: `/` renders the phone `App` (unchanged), `/care` and `/care/*` render `care/CareApp.tsx`, lazy-loaded so the phone bundle and CSS stay as they were (phone CSS build output verified byte-identical to `main`). `lib/pathname.ts` (`usePathname`, `navigateTo` = `history.pushState`, `replacePath`) keeps browser back/forward working; no router dependency. Routes and the redirect rule live in `care/routing.ts`: `/care` landing, `/care/sign-in`, `/care/week`, `/care/alerts`, `/care/settings`; signed-in pages without a persona `replaceState` to the picker; unknown `/care/*` paths show the landing.
- **Deep links on Vercel.** `mobile/vercel.json` rewrites `/care` and `/care/:path*` to `/index.html` (Root Directory is `mobile`). P1's EdgeOne copy needs the same SPA rewrite for `/care/*`.
- **Demo sign-in (front end only).** `/care/sign-in` lists three personas from `care/data/personas.ts`: the senior (name from `summary.senior.name`; choosing her opens `/`), the caretaker who **gets check-ins** (`summary.caregiver.name`, mock "Jamie" if the API has none) and the caretaker with **updates only** (mock slot `MOCK_UPDATES_ONLY_CARETAKER`, "Alex", in `care/data/mock.ts`). The chosen caretaker slot (`checkIns` / `updatesOnly`, not a name) is kept in `sessionStorage` key `pawtner.care.persona` (wrapped in try/catch); Log out clears it and returns to `/care`. No passwords, accounts or database changes.
- **Visibility.** Rules in `care/lib/rules.ts`: updates-only caretakers don't see caring moments of kind `check_in` (`visibleMoments`), and see Alerts read-only with a calm note; `checkInLock()` allows editing the threshold only for the check-ins caretaker, with consent on (`escalation.optedIn`) and the API reachable.
- **Data mapping.** Today ring = `today.doses` taken / total (counts only, never medicine names). Streak = `dog.streak`; seven weekday hearts, the last `min(streak, 7)` filled (`streakHearts`, `recentDays`). Caring moments = `summary.caringMoments` (time via `Intl` in the viewer's local zone; the API has no senior time zone yet). Questions for the doctor = `summary.doctorQuestions`. Consent = `escalation.optedIn`; one shared threshold stepper, minimum `DEMO_RULES.caretakerMinimumThreshold`, saved with the existing `api.updateEscalationSettings({ optedIn, threshold })`. Message preview = `care.web.alerts.preview` in `en.json` with the senior's name and the threshold, no medicine name. Settings shows dog and senior names from data, a weekly-summary preview (visible moments, streak, walks, doctor-question count) and "Medication editing: coming soon".
- **Treat and restock (This week, tentative).** "Send Buddy a treat" (`care/hooks/useCareTreat.ts`) calls the same `api.sendTreat(message)` (POST `/api/treats`) the phone used, with the message "{{caretaker}} sent {{dog}} a treat!" so Rose's gift chip says who sent it; offline the button is disabled with a calm notice. A pending restock request from the phone (`usePendingRestockRequest`, same-origin localStorage, synced across tabs by the `storage` event) shows as "Rose would like help with a medicine refill (about 4 days left)", never the medicine name; "I'll handle it" marks it handled (the phone then says Jamie will help; OK hides it for today). Demo only: works when `/care` runs in the same browser as the phone app. To wire it: P1 adds a table + `POST /api/restock-requests`, `GET ?status=pending`, `POST /:id/handled` (shapes in `lib/restockHelp.ts`), then swap the bodies of `requestRestockHelp`, `readRestockHelp`, `markRestockHelpHandled`.
- **Offline.** `care/hooks/useCareData.ts` calls the three endpoints once; any failure is logged to the console and replaced by `buildMockCareData()` (typed like the API responses), and the page shows `care.web.notice.offline`. Saving is disabled offline.
- **Look.** `care/care.css` holds one token block scoped to `.care-root` (cream/forest palette, Inter, radii, spacing); every class starts with `care-`. The dog is ours (`DOG_IMAGE_BY_MOOD` from `config/scene.ts`, by `dog.mood`); the design's cartoon dog is not used. Garden art: `public/assets/care-garden.webp` (1920×800, 121 KB, from the design's 2.8 MB PNG), path in `care/config.ts`.
- **Mocks to replace** when P1 adds them: the updates-only caretaker (needs `caregivers: { id, name, receivesCheckIns }[]` in `CaretakerSummaryResponse`), the check-ins caretaker fallback when `summary.caregiver` is null, and the senior's time zone for moment times.

Accessories on the dog (`components/PetAccessory.tsx`) are placed by `config/accessories.ts` in % of the dog image (crown ~8%, ears ~4–20%, eyes ~39% of `dog-base.webp`); the hibiscus is an inline SVG (colours as CSS custom properties on `.accessory-flower`). The sun hat box is top 3%, 82% wide, 23% tall (2deg): crown ~49% of the dog's width from ~4%, brim ~18–25% on the forehead above the ear bases (crown/brim proportions in `.accessory-hat`, index.css); checked on the base, joyful and sleepy art. Short landscape (max-height 430px) uses a compact dock (68px) so the card keeps its height (`claude/accessory-landscape-fix`). In landscape, Home's cards rest just above the dock (first card gets `margin-top: auto`), spare height above them; a column taller than the pane still scrolls from its top (`claude/hat-fit-landscape`).

Config lives in `mobile/src/config/` (`scene.ts`: images incl. `DOG_IMAGE_BY_MOOD` (sleepy and joyful have their own art; content and attentive use the base art; a mood image that fails to load falls back to `DOG_BASE_IMAGE`), ground line, dog size limits, screens without the dog; `intro.ts`: dedication timing). Text lives in `mobile/src/locales/en.json`; dog and caretaker names are interpolated from mock data (`{{name}}`, PR #4).

## Known risks

1. The shared Supabase database currently has no Pawtner schema; local `/api/today` reports this until migrations and fictional seed are run with `DATABASE_URL_DIRECT`.
2. API failures: `reportApiProblem()` in `App.tsx` logs the detail to the console; background loads show one `toast.apiOffline` per outage, failed user actions always show `toast.apiActionFailed` (PR #7). The BP form, simulated walk and "Taken" fall back to local `decide()` when the API is unreachable. On "Taken" the failure shows the once-per-outage `toast.apiOffline`, not `toast.apiActionFailed` (the dose is shown as taken locally); the heart-gained toast that follows replaces it at once in the single toast slot, so offline the senior sees only the heart. If `/api/today` loaded earlier and the API drops later, the stale `today` keeps supplying heart and mood, so the offline "Taken" does not change them.
3. At 360×640 the Home decision row (~56 px) crops the top of the dog's head slightly once a decision exists.
4. No authentication or roles exist; this API is for the fictional single-user demo only.
5. Dog size limits and mood looks are TENTATIVE guesses.
6. Fixed names remain in mock data (`mock/care.ts` "Mum + Jamie", `mock/milestones.ts` "From Jamie").
7. `README.md` is stale (says the Vite app doesn't exist); `CLAUDE.md` points to `docs/PRD.md` and a missing `docs/ARCHITECTURE.md`.
8. Landscape two-column layout (phones and tablets held sideways) is checked in headless Chromium at 844×390, 932×430, 740×360, 1024×768 and 1180×820, not yet on a real device. At 740×360 the card is ~230 px tall (scrolls).
